    And the small things

    • Several boards in tabs. Agents on the other boards keep running.
    • Each Claude Code and Codex tile resumes its exact session after a restart.
    • A glow, a sound and a system notification when an agent finishes.
    • Usage of your Claude and Codex plans, as a drawer or as a tile on the map.
    • Find any tile on any board with Ctrl Shift F. Blow one terminal up over the whole map with Ctrl Shift M.
    • Undo and redo for positions and groups. Up to ten board backups.
    • Eight themes, your own accent color, English and French.
    • Diagnostics: where each agent's command was found, its version, its hooks.
    Waiting for you

    Agents ask. You answer from wherever you are.

    When an agent needs a permission, a notch slides out of the inbox in the top bar. For a plain yes or no, you answer right there, without hunting for the tile. For a question or a plan, it takes you to the terminal.

    Orchestra never approves anything on its own. The notch only passes on your click.

    On your machine

    Everything Orchestra touches, listed.

    It starts the CLIs you already use, with your own accounts. No Orchestra account, no API key, no server of ours in the middle.

    127.0.0.1
    A small local server that agents use to reach Orchestra. Random port, secret token that changes at every launch.
    %APPDATA%\Orchestra
    Settings, boards, tasks, templates. On macOS: ~/Library/Application Support/Orchestra. The log and the inbox stay in memory.
    ~/.claude.json
    Marks a folder as trusted before launching Claude Code in it, so it doesn't ask again. Can be turned off.
    ~/.codex/
    orchestra.config.toml, a separate profile, and Orchestra's entries in hooks.json. Your config.toml is never changed, and both do nothing outside Orchestra.
    git
    fetch, worktree add when you pick a branch, and read-only commands. It never commits and never pushes.
    api.github.com
    One request at startup to check for a new version. The only network access of the app itself, and it can be turned off.

      FAQ

      Questions people ask first.

      Do I need an API key?

      No. Orchestra launches the CLIs you already installed and logged into, with your own subscriptions.

      Which agents can use links?

      Claude Code and Codex can relay, delegate, drive a terminal, use linked notes and run task sequences. Other CLIs (Gemini CLI, Aider, your own…) run in a tile and can receive relayed messages. Their status comes from terminal activity.

      Does my code leave my machine?

      Not through Orchestra. Your agents talk to their own providers exactly as they do in a normal terminal.

      Will it eat my subscription faster?

      It can. Every tile uses your own plan, and linked agents that keep handing work to each other add up. Keep turn limits low and switch off the links you don't need. The Usage panel shows where you stand.

      What can agents do on my computer?

      The same as in your own terminal: each tile runs the real CLI in the folder you picked, with that CLI's permission settings. Orchestra's own tools are pre-approved, except running a command in a linked terminal, which always asks.

      Codex asks me to approve “5 hooks”.

      Those are Orchestra's status hooks (working, done). Choose Trust all and continue once and Codex remembers it.

      Can I add another CLI?

      Yes, in Settings › Agents. Pick a known one or add your own command, logo and color. Test checks that the command exists.

      Linux?

      Not yet. Orchestra is built and tested on Windows and macOS (Apple Silicon and Intel).
